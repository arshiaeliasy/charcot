## ✨ امکانات

- 📚 **۸ بخش آموزشی**: علوم پایه (۱۹ درس)، فیزیوپاتولوژی، استاجری (۱۴ کورس)، پره‌انترنی، اینترنی، کیس‌های بالینی، یادداشت‌های بالینی و درباره ما
- 🔎 **جستجوی دو لایه با `Ctrl + K`** — لایهٔ اول عنوان‌ها و فهرست راهنما (آنی)، لایهٔ دوم **متن کامل ۱۲۵ بخش** از فایل `js/search-index.json` که فقط هنگام جستجو دانلود می‌شود
- 🌙 **تم روز/شب** با ذخیره در حافظهٔ مرورگر (بدون پرش هنگام بارگذاری، همخوان با رنگ نوار مرورگر موبایل)
- 📑 **فهرست چسبان بخش‌ها** در دسکتاپ برای صفحه‌های آکاردئونی، با هایلایت بخش جاری و کلیکِ باز‌کنندهٔ همان بخش
- 🔐 **ورود/ثبت‌نام و بازیابی رمز عبور** با Supabase (کتابخانه خودمیزبان + چند مسیر جایگزین)
- 🖼️ **تصویر پیش‌نمایش اختصاصی هر صفحه** (۱۲ تصویر روشن و خوانا در `img/og/`) برای تلگرام و شبکه‌های اجتماعی
- 🔗 **داده ساختاریافتهٔ JSON-LD** روی هر صفحه + `canonical` و Open Graph/Twitter
- ⚖️ **یادآوری آموزشی (سلب مسئولیت)** در فوتر همهٔ صفحه‌ها
- 🖨️ **حالت چاپ دانشجویی** — با `Ctrl + P` همهٔ آکاردئون‌ها باز، ناوبری حذف و متن سیاه روی سفید چاپ می‌شود
- 📱 **ریسپانسیو کامل** با منوی موبایل بهینه
- 🗂️ **آکاردئون‌های قابل لینک** — هر موضوع آدرس یکتای `#hash` دارد
- 🔔 **Toast** به‌جای `alert()` برای پیام‌ها
- ⬆️ **دکمه بازگشت به بالا** و نوار پیشرفت اسکرول
- ⚡ **ساختار سبک استاتیک** — بدون فریم‌ورک، بدون مرحلهٔ بیلد در زمان اجرا (آیکون‌ها، لوگو، QR و فونت همه محلی)

## 🚀 اجرا به‌صورت محلی

```bash
python -m http.server 8123
# سپس http://localhost:8123 را باز کنید
```

> جستجوی متن کامل با `fetch` کار می‌کند؛ اگر فایل را با `file://` باز کنی،
> جستجوی عنوان‌ها کار می‌کند و جستجوی متن بی‌صدا غیرفعال می‌ماند. برای تست کامل از سرور محلی استفاده کن.

## 🌐 انتشار رایگان روی GitHub Pages

1. این مخزن را با `git push` به‌روز کنید
2. در تنظیمات مخزن → **Pages** → Source: `Deploy from a branch` → شاخه `main`
3. سایت چند دقیقه بعد روی `https://<username>.github.io/charcot/` فعال می‌شود

## 🗄️ دیتابیس (اختیاری)

برای فعال‌سازی ثبت‌نام کاربران، مراحل ۵ گانهٔ [DATABASE.md](DATABASE.md) را دنبال کنید.

## 🔐 ورود و ثبت‌نام چطور کار می‌کند؟

- `js/auth.js` کتابخانهٔ `supabase-js` را با چند مسیر جایگزین لود می‌کند:
  `js/vendor/supabase.js` ← jsdelivr ← unpkg ← مسیر پیش‌فرض jsdelivr.
  اگر همه شکست بخورند، به‌جای «فرم بی‌صدا از کار افتاده» یک پیام روشن نمایش داده می‌شود
  و بقیهٔ سایت سالم می‌ماند.
- **خودمیزبانی انجام شده:** کتابخانهٔ `@supabase/supabase-js` نسخهٔ `2.119.2`
  (ساخت UMD) داخل `js/vendor/supabase.js` قرار گرفته است؛ پس فرم‌های ورود
  به CDN وابسته نیستند و در شرایط قطعی/فیلترینگ هم کار می‌کنند. مسیرهای CDN
  فقط به‌عنوان جایگزین پشتیبان باقی مانده‌اند.
  برای به‌روزرسانی: فایل UMD نسخهٔ تازه را از
  `https://cdn.jsdelivr.net/npm/@supabase/supabase-js@<version>/dist/umd/supabase.js`
  دانلود کن و کل محتوای `js/vendor/supabase.js` را با آن عوض کن (سرصفحهٔ مجوز را نگه دار).
- جریان **تعیین رمز عبور جدید** بعد از کلیک روی لینک ایمیل، در همان صفحهٔ اصلی انجام می‌شود
  (فرم «تعیین رمز عبور جدید» به‌صورت خودکار باز می‌شود).
- **پیام‌های خطای فارسی:** خطاهای `supabase-js` (ایمیل تکراری، رمز ضعیف، محدودیت نرخ،
  لینک منقضی، ایمیل تأییدنشده) به پیام قابل‌فهم فارسی ترجمه می‌شوند و به‌صورت Toast/Notice
  نمایش داده می‌شوند؛ هیچ خطای خام انگلیسی به کاربر نشان داده نمی‌شود.
- اگر در Supabase گزینهٔ **Confirm email** روشن باشد، رکورد پروفایل هنگام ثبت‌نام ساخته
  نمی‌شود (چون هنوز نشستی وجود ندارد و RLS اجازه نمی‌دهد)؛ در نخستین ورود موفق
  به‌صورت خودکار ساخته می‌شود.
- ⚠️ پس از انتشار روی دامنهٔ نهایی، در Supabase → Authentication → URL Configuration
  مقدار `Site URL` و `Redirect URLs` را روی `https://<username>.github.io/charcot/`
  تنظیم کن، وگرنه لینک بازیابی رمز به آدرس اشتباه برمی‌گردد.

## 🏥 صفحهٔ استاجری

`externship.html` مثل `clinical-notes.html` و `basic-sciences.html` آکاردئونی است:
هر ۱۴ کورس (۴ ماژور + ۱۰ مینور) یک بخش بازشو با `id` یکتا دارد
(`internal-medicine`، `general-surgery`، `pediatrics`، `obgyn`، `neurology`، ...)،
پس هر کورس آدرس مستقیم و قابل‌اشتراک دارد و با `Ctrl + K` هم مستقیم باز می‌شود.
هر کورس شامل: معرفی کوتاه، مهارت‌های کلیدی، تجربه‌های بخش، چیپ‌های نکته و
نکتهٔ امتحانی/خطای رایج است.

## 🔎 جستجوی متن کامل

`js/search-index.json` ایندکس آمادهٔ جستجو است (صفحه → بخش → متن) و هنگام تایپ
بار اول فقط یک‌بار دانلود می‌شود (~۱۷۰KB، کش‌شده). قواعد ساخت آن:

- هر آکاردئون یک بخش با لنگر `#id` خودش است.
- صفحه‌های بدون آکاردئون بر اساس سرفصل‌ها بخش‌بندی می‌شوند.
- متن هدر/فوتر/منو/اسکریپت هرگز ایندکس نمی‌شود.
- در صفحهٔ اصلی فقط بخش‌های توضیحی (نه کارت‌های ناوبری) ایندکس می‌شوند.
- نرمال‌سازی فارسی: `ي/ك` عربی، نیم‌فاصله و اعراب یکسان‌سازی می‌شوند؛
  پس «کورس‌های» و «کورس های» یک نتیجه می‌دهند.

> **بعد از هر تغییر محتوا این را اجرا کن:**
> `python tools/make_search_index.py`

## 🛠️ اسکریپت‌های ساخت، تست و راستی‌آزمایی

نیاز به پایتون + Pillow (بدون وابستگی بیرونی و بدون اینترنت):

```bash
python tools/check_site.py          # لینک شکسته، متادیتای ناقص، شناسهٔ تکراری، تصویر بدون alt
python tools/check_template.py      # یکسان بودن هدر/فوتر/سلب مسئولیت/JSON-LD/منو در همهٔ صفحه‌ها
python tools/verify_changes.py      # ساختار h1، سلب مسئولیت، JSON-LD، og اختصاصی، ایندکس جستجو، رنگ تم
python tools/fix_pages.py           # اصلاح h1/برند + افزودن سلب مسئولیت و JSON-LD به همهٔ صفحه‌ها
python tools/inject_features.py     # افزودن «فهرست چسبان بخش‌ها» به js/main.js (یک‌بار)
python tools/update_metadata.py     # هم‌گام‌سازی og:image/twitter:image هر صفحه با تصویر خودش
python tools/make_og_images.py      # ساخت img/og/*.jpg (تصویر پیش‌نمایش اختصاصی هر صفحه)
python tools/make_og_images.py --selftest   # بررسی روشنایی/خوانایی تصاویر og
python tools/fa_text.py             # تست شکلسازی و چیدمان راست‌به‌چپ متن فارسی (Pillow)
python tools/make_search_index.py   # ساخت js/search-index.json برای جستجوی متن کامل
python tools/make_sitemap.py        # ساخت sitemap.xml با lastmod واقعی از mtime صفحه‌ها
python tools/make_sitemap.py --selftest   # بررسی درستی sitemap و وجود تصاویر og
python tools/make_assets.py         # آیکون‌ها، لوگو و تصویر پیش‌فرض og
python tools/shrink_assets.py       # سبک‌سازی لوگو و favicon (پالت محدود + حذف اندازه‌های اضافی)
python tools/make_qr.py             # ساخت img/qr.svg و img/qr.png (QR محلی، بدون سرویس بیرونی)
python tools/make_qr.py --selftest  # بررسی صحت انکودر QR
```

تست رفتار فرانت‌اند بدون مرورگر (Node، بدون وابستگی):

```bash
node tools/runtime_test.mjs   # آکاردئون، theme-color، نوار پیشرفت، فهرست بخش‌ها، باز شدن پنجرهٔ جستجو
node tools/search_test.mjs    # موتور جستجوی متن روی ایندکس واقعی (نیم‌فاصله، ریشه‌یابی، بی‌ربط‌ها)
```

## 🎨 تم و رنگ نوار مرورگر

رنگ نوار مرورگر موبایل از متغیر CSS `--theme-color` خوانده می‌شود
(`:root` مقدار تیره و `[data-theme="light"]` مقدار روشن). هم اسکریپت هد
(برای جلوگیری از پرش) و هم `js/main.js` همین متغیر را می‌خوانند؛ پس با تغییر تم،
رنگ نوار مرورگر بلافاصله به‌روز می‌شود و مقدار تکراری هگز در چند فایل پخش نشده است.

رنگ‌های تأکیدی برای «متن» جدا از رنگ‌های «تزئینی» هستند تا کنتراست در تم روشن حفظ شود:

- `--accent-ink` / `--accent-ink-blue` — متن تأکیدی (تم روشن: `#0B6E66` / `#0369A1`)
- `--danger-ink` — متن خطا (تم روشن: `#B91C1C`)
- `--case-link` — لینک کارت کیس‌ها

## 🧩 ساختار هدینگ و دسترس‌پذیری

هر صفحه **دقیقاً یک `<h1>`** دارد و آن عنوان خودِ صفحه است (نه نام سایت).
نام سایت در `.brand-name` داخل هدر است. دلیل: موتور جستجو و screen-reader باید
هر صفحه را از صفحهٔ دیگر تشخیص دهد.

بقیهٔ نکات: `aria-expanded` روی آکاردئون‌ها و منوی موبایل، `role="tab"` روی تب‌های
ورود، `aria-hidden` روی آیکون‌های تزئینی، `focus-visible` روی همهٔ کنترل‌ها،
احترام به `prefers-reduced-motion` و `alt` روی همهٔ تصاویر.
